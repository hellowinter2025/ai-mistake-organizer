# 错题录入：图片 → 题库

**核心事实：读图由 WorkBuddy 自身的多模态能力完成**（主智能体，或并行派发的子智能体），
不调用项目里的任何 AI 接口。脚本 `scripts/*.py` 只做本地事——上传、裁剪、拼图、自检、入库。
项目里那条 `POST /api/ai/solve`（裁图 + 调模型）**绝对不要用**，它每道题都会烧一次 API 额度。
子智能体是 WorkBuddy 内置能力，和 `/api/ai/*` 是两回事，不冲突。

## 0. 环境

| 项 | 值 |
| --- | --- |
| 项目根 | 脚本自动探测（`--root` 或环境变量 `MM_ROOT` 可覆盖） |
| 服务 | `http://127.0.0.1:8765`（启动：双击 `启动.vbs`） |
| Python | `<项目根>/.venv/Scripts/python.exe`（脚本依赖 httpx / Pillow，必须用它跑） |
| 主脚本 | `~/.workbuddy/skills/错题录入/scripts/mm.py`（随仓库分发时在 `skills/错题录入/`） |
| 辅助脚本 | 同目录 `contact.py`（放大联系表）、`check_batch.py`（内容自检）、`redmarks.py`（红笔抠图） |
| 临时裁图 | `%TEMP%/mm_intake/` |

第一条命令永远是 `mm.py health`。连不上就告诉用户「先双击 启动.vbs」，
**不要**自己起服务顶掉用户正在用的那个进程。

```bash
MM="<项目根>/.venv/Scripts/python.exe ~/.workbuddy/skills/错题录入/scripts/mm.py"
PY="<项目根>/.venv/Scripts/python.exe"
S="~/.workbuddy/skills/错题录入/scripts"
```

## 1. 流程（每批图都按这个走）

```
⓪ $MM health                                  → 一条命令确认服务
① $MM upload <目录>                           → 一次传完所有图，拿 image_id
② $MM preview / bands（全部图，并行）          → 一次定好所有裁区边界
③ $MM crop 每条 --span 一次给全               → 每题一个 crop_token + 本地裁图
④ $PY $S/contact.py --spec spec.json --out marks.png
                                              → 一张联系表覆盖全部批改痕迹 + 疑难符号 + 原题图
⑤ 并行派发子智能体：一卷一个，逐字转录 + 批改判定，回 JSON
⑥ 主智能体复核：所有 unclear / uncertain / 有图的题，回原图确认
⑦ 批量写解析 → 合成 batch.json（一次 Write，不要每题一个文件）
⑧ 有图：放大原卷图 → 列要素清单 → 写 TikZ → render → 打开 PNG 与原卷并排核对
⑨ $PY $S/check_batch.py batch.json && $MM add batch.json --dry-run
⑩ $MM add batch.json → $MM get <编号> --json 回读
```

**只录错题**。整份卷子里判对的题不要入——错题本的价值在"这道我做错了"。
认红笔标记的办法：叉号/划线在选项或答案旁 = 判错；对勾或只圈了正确选项 = 判对；
老师在选项旁写的那个字母（如大写的 `B`）= 标准答案，可用来反推学生选错没选错。
**痕迹矛盾、只有一条斜线、完全没有红笔 → 一律判 `unclear`，不录，收尾时列给用户问。**

### 速度纪律（实测：22 分钟里工具只跑 2.3 分钟，其余都耗在反复看图上）

1. **能并行的绝不串行**：所有独立的 `preview` / `bands` / `crop` / `render` / `ViewImage`
   调用放在同一条消息里一起发；一条 Bash 里用 `&&` 串完有依赖的命令。
2. **疑点只放大一次**：把「所有批改标记 + 所有疑难符号 + 所有原题图形」写成一份
   `spec.json`，第 ④ 步一次拼成联系表、一次看完。**禁止**看一题 → 发现看不清 →
   再裁 → 再放大 → 再回看，这是上次 10 分钟黑洞的主因。
3. **裁区一次定死**：先 `bands` 拿空白带，再对每张图一次性给全 `--span`，别逐题试错。
4. **转录交给子智能体并行**（见 1.5），主智能体只做复核、判断、写解析。
5. **解析成批写**：按「方法 → 触发点 → 推导 → 结论」模板，把整批题一次写进
   `batch.json`，不要一道题一次工具调用。
6. **图形先对照再落笔**（见 3.0），返工比慢更贵。

**关键：③ 之后必须「看一次裁图」再写字段。** 整图缩略后小字必糊，凭整图抄题干
一定会漏下标、错符号。裁出来的图才是抄写依据。

### 裁区的三种写法

`preview` 默认叠**百分比刻度尺**（横线每 0.1、竖线每 0.25，都标了数值）。
先在图上按刻度读出「这道题从 0.18 到 0.35」，再 `--span 0.18:0.35` ——
比对着缩略图肉眼估准得多，实测不用刻度会差 0.02 以上，直接把选项行切掉。

| 写法 | 用途 |
| --- | --- |
| `--span 0.18:0.35` | **首选**。整宽、纵向区间（0~1），试卷基本是单栏纵向排版，一题一条横带 |
| `--span 0.18:0.35 --x 0.0:0.5` | 双栏卷子 / 一张图拍了两页，按栏分开 |
| `--box 120,80,900,420` | 像素框；或给 0~1 的小数（服务端自动识别比例） |
| `--index 2,4-5` | 用 `analyze` 的自动候选编号，最省事但检测粒度很粗 |

**换个更硬的依据：`mm.py bands <id>`**
它用自适应阈值找「水平空白带」，直接把可下刀的位置列成数字：

```
0.112 ~ 0.124   (y=451..497，高 46px)
0.211 ~ 0.221   (y=849..891，高 42px)
```

边界落在空白带里，永远不会切掉半行字。空白带太密或太少时调 `--density`（默认
0.004，手写填满整页时调到 0.02）和 `--min-height`（默认 10）。

**边界怎么取**：
- 取在相邻两题之间的**空白行**上，宁可多留一点白，也不要把下一题的题号框进来。
- 裁完**必须打开裁图看一眼**（`--save-dir` 会把图存到本地）。常见的两种偏差：
  选项最后一行被切掉 → 把上界 `+0.01`；框进来上一题的尾巴 → 把下界 `+0.01`。
- 自动切题（`--index`）在密集试卷上往往只给出「上半天 / 下半天」两三大块，
  别指望它一题一块；它的价值是给出大致分区，细切还是靠 `--span`。

**密排卷子（手写填满、行距很紧）的省力打法**：
逐题精裁容易反复试错，改成先按「题组」裁一块大的（比如 `--span 0.18:0.38`
覆盖两题），一张图就把两三道题的题干和选项读全；确定边界后再精裁入库。
读题用大块、入库用精裁，来回次数能少一半。

**手机横拍的卷子**（长边 4032 那种）：题目仍然是从上到下排的，`--span` 照常用，
不要因为图是横的就去找 `--x`。只有「一张图里左右并排两个版面」才需要 `--x`。

`crop` 加 `--save-dir %TEMP%/mm_intake/<这批的名字>`，脚本会把每张裁图下载到
本地并打印路径，直接 `Read` 那个路径看图。

## 1.5 子智能体并行判读（≥2 张图或 ≥6 道题时启用）

**分工边界**：子智能体只做「逐字转录 + 批改痕迹判定 + 图形要素描述」这类可校验的
体力活；**判对错、定标准答案、写解析、重绘图形、入库，全部由主智能体负责**。
子智能体的输出一律当**初稿**，不能直接用。

派发方式：同一条消息里发多个 `Agent` 调用（`subagent_type: general-purpose`，
它有 ViewImage）即为并行，**一卷一个**，把该卷所有裁图的绝对路径交给它。
不要 `run_in_background`（要拿到结果才能继续）。

### 子智能体提示词模板

```
你是「错题转录员」。只做逐字抄录与批改判定，不写标准答案、不写解析、不入库、不调任何脚本/接口。
图片（按题号顺序，全部要逐张打开看）：<绝对路径列表>
对应的 crop_token：<列表>

逐题输出一个 JSON 数组，每题一个对象：
{
 "q_no": "8",
 "stem": "逐字抄录完整题干和所有选项，公式用 $...$，多行用真换行",
 "student_answer": "学生黑笔写的内容，没有就空串",
 "teacher_mark": "红笔痕迹：叉/勾/划线/圈/写的字母数字，各在什么位置",
 "verdict": "wrong | right | unclear",
 "figure_desc": "原题有图才写：立体还是平面、实线虚线怎么分、全部标注字母、
                 有没有轴线/直径/截面椭圆、各点落在哪条线上",
 "uncertain": ["看不清的点，写明位置和两三种候选读法"],
 "crop_token": "<本题 token>"
}

规则：
- 看不清的字符用 □ 占位并写进 uncertain，禁止猜、禁止凭上下文补全。
- 区间开闭、上下标、根号、分式、指数、希腊字母、大小写、正负号逐项确认，存疑进 uncertain。
- verdict 只按红笔痕迹判；没有红笔、痕迹矛盾、只有一条斜线 → 一律 unclear。
- figure_desc 要具体到「CD、EF 是底面圆上互相垂直的直径，虚线过圆心 O₁」这种程度，
  它会被用来重绘图形。
- 不要把红笔批注、对勾、分数抄进 stem。
最后只输出 JSON，不要任何解释文字。
```

### 主智能体复核（不可省，这是质量闸门）

拿到各子智能体的 JSON 后，逐条过：

1. **所有 `verdict != right` 的题**：回裁图/联系表亲眼确认红笔，别信转录。
2. **所有 `uncertain` 非空**：用 `contact.py` 把该处放大到能看清，确认不了就
   `□` + `notes` 留痕，**不许二选一蒙一个**。
3. **所有公式**：按 2.4 的符号清单逐项对照放大图。
4. **所有 `figure_desc` 非空的题**：走 3.0 原卷图对照流程，不能凭描述画图。
5. **两个子智能体结论冲突 / 转录与主智能体印象冲突**：一律回原图放大，不投票、不折中。

## 1.6 放大联系表（`contact.py`）

把「批改标记 + 疑难符号 + 原题图形」一次拼成一张带编号的图，看一次解决所有疑点：

```bash
# 多图多区域（推荐）：spec.json 里每项 {image, box:[x1,y1,x2,y2], label}
$PY $S/contact.py --spec spec.json --out %TEMP%/mm_intake/marks.png --cols 2 --width 780

# 单图少区域
$PY $S/contact.py --image IMG --box 0.70,0.09,0.98,0.17 --label "p1q7 mark" \
    --box 0.55,0.23,0.83,0.40 --label "p1q8 figure" --out marks.png
```

- `box` 是相对**整张原图**的 0~1 比例，`preview` 的刻度尺可以直接读。
- 标签用 ASCII（编号自动补在前面），联系表每格左上角有黄底编号，看图时按号回答。
- 批改痕迹区域给 `--width 780` 足够；**题目原图建议单独给 1400~1600**，
  或把它单独拼一张表——图形要放大到能数清虚线椭圆和标注字母。
- 英语/红笔密集的段落，配合 `redmarks.py mask / spans` 先定位有几处批改。

## 2. 字段口径（决定这份题库好不好用）

| 字段 | 写法 |
| --- | --- |
| `subject` | 数学 / 物理 / 化学 / 生物 / 语文 / 英语 / 历史 / 地理 / 政治。**按图判，不要按题号猜**；化学方程式、实验装置图别记成数学 |
| `question_type` | `选择题（单选）` `选择题（多选）` `填空题` `解答题` `证明题` `其他`。多选由你判断：正确项 ≥2 就是多选 |
| `stem` | 完整题干、所有选项，公式用 `$...$`。多行用**真换行**（`\n` 转义），不要写成字面量 `\n`。选择题保留「（　　）」占位。**不要**把红笔批注、对勾、分数抄进题干 |
| `answer` | 选择题只写字母，多选按字母序连写（`ACD`）；填空题按空序给出；解答题只给最终结果并带单位，不写过程 |
| `error_reason` | 学生的错因，落到**方法/思路/概念**层面（"把单调区间当成定义域用"），不要写"计算粗心"这种不可行动的话。图上有批改痕迹时据此还原错在哪一步 |
| `solution_fix` | 三段：`方法：<教材上的通用叫法>` → `触发点：<题干里让你想到它的那个特征>` → 完整推导。关键步骤补一句为什么能这么做；换元写新变量范围；分类讨论交代依据与边界取不取；末句结论与 `answer` 一致 |
| `solution_alt` | 确实更巧的解法才写，`另法：<名称>` + 两三句说清省在哪；没有就留空，不要硬凑 |
| `knowledge_points` | 数组，2~4 个，用教材上的知识点名（"线面垂直的判定"），不要写章节号 |
| `difficulty` | 1~5 整数。1 课本例题级，3 常规考试中档，5 压轴 |
| `notes` | 只写你**确实不确定**的地方：字迹看不清、图缺了一块、答案被涂掉、**答案是自主推导而非原卷给出**。这些要让人来补 |
| `_figure_checked` | 本地标记，有 `figure_tikz` 且已渲染目视核对过就置 `true`；`add` 会忽略这个字段，不会写进库 |

方法名用你判断题目时真正用到的那一招，不要为了填字段编一个。

### 2.1 数学 / 物理：解析必须有「方法」和「触发点」

`solution_fix` 第一行 `方法：<教材上的通用叫法>`，第二行 `触发点：<看到什么条件想到它>`，
之后才是推导。旧题如果只有一串推导，**补这两行**（按原解析实际用的方法写，不要另编）。

### 2.2 化学：只给字母等于没写

化学的选择题答案就是字母，**详细内容全在 `solution_fix`**，四块缺一不可：

1. **逐项分析**：A、B、C、D 各一段，先给「正确/错误」，再给依据；
2. **方程式**：涉及反应就写配平的化学方程式或离子方程式，带条件与 ↑↓
   （`$\ce{MnO2 + 4HCl(conc) ->[\Delta] MnCl2 + Cl2 ^ + 2H2O}$`）；
3. **知识点**：一句能迁移的规律（「醇羟基不与 $\ce{NaOH}$ 反应，酚羟基、羧基才反应」）；
4. **易混点**：学生最容易混的那一条，一句话点破。

化学**不要**写「方法：」「触发点：」（那是数学物理的格式）。错因写「把 X 当成 Y」。

### 2.3 英语：只录错题，且必须给翻译

- **只收学生做错的空**：语法填空十空错三空就只出三条；答对的空直接把答案填回句子里，
  不要留 `_____`。全对不入库（误录了就把 `stem` 写成「(1) 未发现错题」）。
- 判据优先级：**红笔批改痕迹 > 学生答案与语法规则是否相符**。
- 四栏对齐：挖空句 / 答案 / 语法点 / **该句中文翻译**（写在 `solution_fix`）。
- 长难句翻译后补一句结构说明：主干是什么、哪个从句或分词修饰谁。
- 英语不出 LaTeX、不用表格。

**先找红笔，再看句子**：一整段上学生答案和老师批改糊在一起，凭肉眼按比例裁
很容易把隔壁那一空的订正读成这一空的。用脚本把红笔单独抠出来，一簇一处：

```bash
python scripts/redmarks.py mask  <原图> --out red.jpg     # 一眼看出有几处批改
python scripts/redmarks.py spans <原图> --outdir red/     # 每处一张带上下文的小图
```

红笔只有两三处，就说明这一段只错了那两三空——**别把整段十空都抄下来**。
学生自己在答卷上划掉的（黑笔）不算判据：确认过多次，划掉的答案也可能本来就是对的。
没有红笔、但学生写的明显不合语法（如 `with records of their cultivation appeared`），
照样算错题，写进 `notes` 说明依据。

### 2.4 准确性红线（产物质量的核心）

**不确定就留痕**：看不清的符号用 `□` 占位并在 `notes` 说明，比猜一个错值好——
猜错的值会让用户以为题抄对了。**禁止**为了让字段好看，把看不清的地方按"最像的"补上。

**题干符号清单**（写完逐项回放大图对一遍，错一个就是一道废题）：
下标/上标（$S_{n+1}$ 不是 $S_n+1$）、根号与分式范围、指数符号与底数、
区间开闭（`[0,5)` ≠ `(0,5)`）、希腊字母、字母大小写、选项字母、正负号、
题干里的「⊥ / ∥ / ∈ / ∀」、单位。

**答案验证**（`answer` 是学生真正要看到的字段，不许想当然）：
1. 多选题**逐项**给判断依据，A/B/C/D 每一个都要在解析里有结论；漏选/误选的错因
   要和答案对得上（错因说「漏选 C」而答案里没有 C = 自相矛盾）。
2. 能算的**用 Python / sympy 数值或符号验算一遍**（递推求通项、求和、极值、
   向量夹角、截面面积等），别只靠心算；算出的结果与 `answer` 不一致就回去改。
3. `solution_fix` 末句结论必须与 `answer` 完全一致。
4. 原卷红笔**没写**标准答案、答案是自己推出来的 → `notes` 里必须写
   「原卷未给标准答案，X 为自主推导结果」。
5. 题干有多义读法（如区间开闭、`4n` 还是 `4^n`），把另一种读法在 `notes`
   里注明，并说明答案是否受影响。

**交叉复核**：子智能体转录 vs 主智能体判断有分歧 → 回原图放大，不投票。
**不臆造**：原卷没给的分数、老师没写的评语、看不清的图形，一律不进字段。

## 3. 图形：默认自己画，画完必须自己看一遍

**默认画。** 题干里有图，就给 `figure_tikz`。贴原题截图是退路——截图里带着学生笔迹、
红叉、纸面阴影，印到卷面上很难看，也没法缩放。只有「实拍才看得懂」的图才贴。

| 场景 | 做法 |
| --- | --- |
| 平面几何、立体几何（空间四边形、棱柱棱锥、截面、翻折）、坐标系、函数图像 | `figure_tikz` |
| 统计图、韦恩图、数轴、程序框图、受力分析、运动示意图 | `figure_tikz` |
| 电路**原理**图（符号化的电源/开关/电阻/电表） | `figure_tikz` |
| 化学：电子式、原子轨道表示式、电子排布图、晶胞、工艺流程 | `figure_smiles` / `figure_flow` / `figure_tikz` |
| 化学结构式 | `figure_smiles`（`{"苯酚": "Oc1ccccc1"}`） |
| 实拍照片、实验装置实物（烧瓶/冷凝管/洗气瓶/天平）、电路实物连线、地图、手写压图 | `needs_figure: 1` + **必须** `figure_box` 只框图形 |
| 真的没图 | 三个都不给，`needs_figure: 0` |

### 3.0 重绘之前：必须放大原卷题图对照（硬性）

**这一步省掉，图一定画错。** 上一次把一道圆锥内切球题画成「轴截面三角形 + 内切圆」，
丢了底面两条垂直直径、轴线、切点圆，直接让 B/D 两个选项失去图形依据——返工两轮。

```bash
# 1) 把原题图形单独放大到 1400px 以上（用整图 0~1 坐标）
$PY $S/contact.py --image <原图> --box 0.55,0.235,0.83,0.40 \
    --label "q8 original figure" --out orig_fig.png --cols 1 --width 1500
# 2) 打开这张放大图，逐项列出「图形要素清单」再动笔
```

**要素清单**必须写进你的工作记忆（或在心里逐条对）：
- 立体还是平面？投影方式（底面椭圆？斜二测？）
- 所有标注字母及其位置，哪个点在哪条线/哪个面上；
- 哪些线是实线、哪些是**虚线**（被挡的棱、底面的后半椭圆、直径、轴线）；
- 有没有**特征截面**：切点圆、球大圆、截面多边形，它们怎么画（虚线椭圆？）；
- 图形与哪个选项直接相关（如「球与侧面的公共点轨迹」= 切点圆）。

**立体几何**：原卷给的往往是透视图。哪条线在图上被挡住、哪条是虚线、哪些辅助线
（直径、轴线、切点圆）原卷画了，就按原卷来——原卷有的要素不能少，原卷没有的不要添。
原卷是透视图时，别自己简化成一张平面剖面图：简化完看着清楚，空间关系却没了，
依赖这些关系的选项会失去依据。学生手写的辅助线、标注的数字不必复刻。

### 3.1 写完 TikZ 必须渲染自检（硬性）

```bash
mm.py render fig.tex                    # 编译 → PNG，打印尺寸/墨迹/标注数/自动修复项
```

然后**用 Read/ViewImage 打开那张 PNG**，逐条对：

1. 点是否落在它该在的线段上（「E 在 AB 上」就绝对不能浮在空中）；
2. 虚线/实线有没有重合打架（被挡的棱只画一次 `[dashed]`）；
3. 所有字母标注都在、没有压在线上、没有被裁掉；
4. 题干给出的平行、垂直、相等、等分等关系，在图上能看出区别；
5. **把渲染图和 3.0 那张原卷放大图并排对一遍**：要素清单里的每一条都在新图里。

**下面只列「容易出问题的地方」，不列固定画法。** 判据永远只有两个：题干文字，和原卷那张图。
同一个几何体，不同题目要用的关系不同，摆法就该跟着变；照搬某个「标准姿势」，
反而容易把本题要用的那条线压平、遮住或画到轮廓外面去。

| 容易出问题的地方 | 具体表现 |
|---|---|
| 空间感 | 立体图形看着是平的，题干里「异面 / 共面 / 不平行」这类关系在图上看不出区别 |
| 尺寸关系 | 图上两段的长度比、某个角的开口，与题干给的数据明显不符 |
| 顶点标注 | 标到体内部、两个标签挤成一团、标签压在某条线上或被裁掉 |
| 特殊位置 | 题干说的是中点、三等分点、切点，图上却落在别处 |
| 动点 | 动点和端点重合，看不出它可以移动 |
| 曲面 | 球、圆、椭圆的前后遮挡关系与切点位置对不上 |
| 辅助线 | 辅助线穿过无关的点，或与轮廓线混在一起分不清 |
| 越界 | 线段伸出图形轮廓之外 |

不对就改代码重跑，直到看得过去。**没看过的图不许入库**——渲染成功≠画对了，
编译通过只能证明语法没错。确认无误后在 `batch.json` 该题标 `_figure_checked: true`。

渲染器会自动做这几件事，不用自己写：`\usetikzlibrary{calc}` 自动加载
（用了 `$(A)!0.5!(B)$` 就够）、写在环境外的库声明会被挪进来、图里的汉字会被删掉。
`fillbetween` 没装，写了整张图作废。**TikZ 源码里不写中文注释**（会被剥离）。

### 3.2 实在要贴图：必须只框图形本体

整段题干截图直接贴上去，导出时会把题干文字和图一起印，和排版出来的题干撞车。
用 `figure` 命令框准：

```bash
mm.py figure AGX2PK --box 0.62,0.10,0.38,0.45          # 只出预览，先看框得准不准
mm.py figure AGX2PK --box 0.62,0.10,0.38,0.45 --apply  # 看对了再写库
```

- `--box` 是**相对整题截图**的 `x,y,w,h`（0~1，也可以给像素）；
- 先跑不带 `--apply` 的版本，打开预览图确认：框住的是图形本体、没有切掉图形边缘、
  没有把题干文字圈进来；写库后脚本会再存一张裁好的图，**再看一次**；
- 批量入库时直接写在 JSON 里：`"figure_box": [x,y,w,h]` + `"needs_figure": 1`。

### 3.3 TikZ 约定

- **TikZ 只写 `\begin{tikzpicture}...\end{tikzpicture}`**，不要 `\documentclass` /
  `\usepackage` / `\begin{document}`；图内不写汉字（没有中文字体，会被删掉）。
- 函数图像用 `pgfplots` 的 `\addplot[domain=a:b]{表达式}`，**不要自己描点连线**。
- 立体图被挡的棱单独写 `\draw[dashed] ...`，不要先画实线再叠虚线（重合等于没画）。
- 标注用 `fill=white` 遮线时，注意别把轮廓线盖断。
- 整幅图控制在 8cm 宽以内。
- 编译不过不影响入库（会自动退回贴原图），但 `notes` 里要记一句。

## 4. 查重

`add` 会自动查：拿题干前 12 字检索、按「去空白去标点」后的全文比对。
命中就跳过并返回已有 `#编号`。

- 用户重复发同一张图是常态（同一份卷子分几次发），跳过是正确行为。
- 真想再录一份（比如同一道题两种错法）加 `--force`。
- 题目被改过（多了一句小问）不算重复，会正常入库。

## 5. 批量节奏（图很多时）

- **一次上传 ≤8 张**（脚本已自动分批）。10 张以上先 `upload` 全部，再逐张处理，
  不要一张一张传——每张一个请求太慢。
- **逐卷推进，不要攒**：一张图的题走完 ⑤~⑩ 就入库，再处理下一张。中途网络/进程挂了
  已入库的不会丢。子智能体也按卷派发，别等所有卷都转录完再写解析。
- 给用户进度反馈时用「第 3/12 张，已入库 7 道」这种格式，别只报总数。
- 超过 20 张先跟用户确认一下（是不是真的要全录），但**不要**因为量大就降低抄写质量，
  也不要为了赶进度跳过 1.5 的复核和 3.0 的图形对照。

### 用户只是把图贴进对话、没给文件路径

先看消息里有没有给本地路径（对话附件通常落在临时目录，`Read`/`ViewImage` 能读到的那个）。
- **有路径** → 正常 `upload`，走完整流程，原题截图能存下来。
- **拿不到路径**（图只在对话里）→ 仍然可以录：省掉 `crop_token`，字段照常写，
  在 `notes` 里写「原题截图未存，需在页面重新框选」。导出时该题没有截图，
  但题干、解析、题图都正常。
- 别为了拿路径去截屏/另存——直接问用户「这批图在哪个文件夹」更快。

## 6. 已有题目要改

`add` 查到重复会自动跳过。但如果库里那条本身就是错的——AI 早期解析的通病是
**答案给错**（如把"一定异面"的答案写成唯一一个不成立的选项）和**错因写"无法辨认笔迹"**
——用 `update` 就地改，不要 `--force` 再录一条出来：

```json
{ "answer": "BCD", "question_type": "选择题（多选）", "error_reason": "…", "solution_fix": "…" }
```

```bash
mm.py update MJEN3T patch.json --verify     # --verify 先跑字段校验，不过就不写
mm.py update MJEN3T patch.json --dry-run    # 只看会发什么
```

- 只写要改的字段，其余原样保留；`stem` 不传就不会被动。
- **图形画错也用 `update`**：patch 里放 `figure_tikz` + `notes`，改完 `get --json` 回读。
- 发现答案有错要**改掉**，别只在 notes 里写一句——学生看到的就是那个答案。
- 旧数据题型写作「选择题」的，顺手补成「选择题（单选）/（多选）」。

## 6.5 存量审阅（用户说「把库里的题重新检查一遍」时）

1. **先跑体检**，不要一上来就逐题读：

   ```bash
   mm.py audit                # 列出不符合口径的题 + 原因
   mm.py audit --subject 化学  # 按学科分治
   ```

   它按第 2 节的口径判：数学缺「方法/触发点」、化学没有逐项分析或方程式、
   英语**单条**里挖了 3 个以上的空（疑似整段照抄）或缺翻译、答案条数与题干条数对不上、
   贴图没框图形、答案/知识点为空。
   （空数是按 `(1)(2)` 每条分别数的：错题本本来就是一条一句，按整段统计会把
   正常的多条题误判成「整段照抄」。）

2. **按学科分批处理**，一科一次 `update`，别混着改（改错了不好回滚）。
3. **化学/英语要重写而不是补字段**：这两科的问题是内容不够，补一个字段没用。
4. 数学的「方法/触发点」缺失属于格式问题：读原解析，按它实际用的方法补两行，
   **不要为了套格式把解析重写一遍**——原文是对的就不动内容。
5. 改完再跑一次 `mm.py audit`，直到 `全部符合口径`；再抽 2~3 道 `get` 回读。
6. 汇报要给数字：改了几道、还剩几道、每道改了什么。

## 6.8 入库前质量门禁（缺一不可）

```bash
$PY $S/check_batch.py batch.json            # 内容自检：公式配对、答案/解析一致性、图形标记、留痕
$MM add batch.json --dry-run                # 字段校验 + 查重
$MM add batch.json                          # 正式入库
$MM get <编号> --json                       # 回读
```

`check_batch.py` 管的是 `mm.py validate` 管不到的**内容自洽**：
`$` 是否配对、字面量 `\n`、stem 里有没有混进批改描述、
`solution_fix` 末段有没有出现 `answer`、数学/物理的两行格式、
错因与多选答案是否打架、`figure_tikz` 是否标了 `_figure_checked`、
`□` 占位有没有在 notes 里说明。有 `ERROR` 就退出码 1，串在 `add` 前面能挡住入库。

**人工再确认四件事**（脚本查不出来）：
1. 每道题的红笔判错结论都亲眼核过（1.5 复核清单）；
2. 多选题 A/B/C/D 逐项有判断依据，能算的验算过（2.4）；
3. 有图的题，渲染图和原卷放大图并排对过要素清单（3.0/3.1）；
4. 所有不确定项都进了 `notes`，没有把猜测写成确定值。

## 7. 收尾

1. `add` 的最后一行会列出 `#编号`；用 `get <编号> --json` **逐道**回读（不只是抽 1~2 道），
   核对：题干完整、`$` 没被吃掉、`answer` 与解析末句一致、`crop_url` 有值、
   有图的题 `figure_tikz` 已写进库。
2. 向用户汇报：**入库几道、编号列表、跳过的重复题、判 `unclear` 没录的题、
   notes 里留了哪些待确认的点**。`unclear` 的题要单独列出来问用户要不要补录。
3. 提醒：页面 Ctrl+F5 刷新；编号会以浅灰印在卷面上，方便核对。

## 8. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| `连不上 http://127.0.0.1:8765` | 服务没起。让用户双击 `启动.vbs`，别自己抢端口 |
| `HTTP 403 ... 访问令牌已失效` | 服务重启过，令牌变了。重新读 `data/.session_token`（脚本每次运行都会读，重跑即可） |
| `HTTP 400 选区太小` | 框小于 20×12 像素，重新 `--span` |
| 裁图里选项最后一行被切掉 | 上界加 0.01~0.02 重裁；对照刻度尺别靠猜 |
| 上传 `HTTP 400` 且提示格式 | PIL 解不开（HEIC 常见）。让用户转成 JPG/PNG，或用系统截图重存 |
| 题干里的公式在页面显示成红字 | `$` 数量不匹配（奇数个）。`check_batch.py` 会提前报出来 |
| 页面上看到 `\n` 两个字符 | 字段里写了字面量，`add` 会拦下报错；改成真换行 |
| 导出的题图是 AI 画的歪图 | 该题应 `needs_figure: 1`（图太复杂画不准），改完重新保存即可 |
| 重绘的图和原卷不像 | 没做 3.0。放大原卷图 → 列要素清单 → 按立体透视重画，`update` 写回 |
| 子智能体把红笔勾看成叉 | 转录只当初稿；主智能体按 1.5 复核清单回原图确认，别直接采信 |
| `contact.py` 标签显示成方块 | 标签用了中文且系统没找到字体，改用 ASCII 标签 |

## 9. 不要做的事

- ❌ 调 `/api/ai/solve`、`/api/ai/test` 或任何 `/api/ai/*` 接口。
- ❌ 把红笔批改、对勾、分数、页眉页码抄进 `stem`。
- ❌ 图看不全时凭想象补全图形或题干——写进 `notes` 交给用户。
- ❌ 导入前不跑 `check_batch.py` 和 `--dry-run`。
- ❌ 为了让「入库数好看」而跳过 `notes`、把不确定的答案填成确定值。
- ❌ 直接采信子智能体的转录/判定去做入库，跳过主智能体复核。
- ❌ 逐题反复裁图放大、逐题单独写文件——联系表一次看完、解析成批写。
- ❌ 没放大原卷题图就凭题干文字画立体几何图（会退化成轴截面）。
- ❌ 多选题不给逐项依据、答案靠"感觉"；解析末句与 `answer` 不一致。

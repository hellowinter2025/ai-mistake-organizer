# 错题录入：图片 → 题库

**核心事实：读图由你（多模态）完成，不调用任何模型接口。**
脚本 `scripts/mm.py` 只做三件本地事——上传、裁剪、入库。项目里那条
`POST /api/ai/solve`（裁图 + 调模型）**绝对不要用**，它每道题都会烧一次 API 额度。

## 0. 环境

| 项 | 值 |
| --- | --- |
| 项目根 | 脚本自动探测（`--root` 或环境变量 `MM_ROOT` 可覆盖） |
| 服务 | `http://127.0.0.1:8765`（启动：双击 `启动.vbs`） |
| Python | `<项目根>/.venv/Scripts/python.exe`（脚本依赖 httpx，必须用它跑） |
| 脚本 | `~/.workbuddy/skills/错题录入/scripts/mm.py`（随仓库分发时在 `skills/错题录入/`） |
| 临时裁图 | `%TEMP%/mm_intake/` |

第一条命令永远是 `mm.py health`。连不上就告诉用户「先双击 启动.vbs」，
**不要**自己起服务顶掉用户正在用的那个进程。

```bash
MM="<项目根>/.venv/Scripts/python.exe ~/.workbuddy/skills/错题录入/scripts/mm.py"
```

## 1. 流程（每批图都按这个走）

```
① mm.py upload <目录或文件...>        → 拿到 image_id + 尺寸
② 看图：Read/ViewImage 整图           → 数清一道图里有几道错题、什么学科
③ mm.py preview <id> --out p.png      → 整图 + 百分比刻度尺（按刻度读 --span）
④ mm.py crop <id> --span 0.18:0.35 …  → 每题一个 crop_token（--save-dir 落本地）
⑤ 看裁图逐题写字段 → 合成 JSON
⑥ mm.py add --json batch.json --dry-run   → 校验通过再正式入库
⑦ mm.py get <编号>                    → 回读确认
```

**关键：④ 之后再「看一次裁图」再写字段。** 整图缩略后小字必糊，凭整图抄题干
一定会漏下标、错符号。裁出来的图才是抄写依据。

### 裁区的三种写法

`preview` 默认叠**百分比刻度尺**（横线每 0.1、竖线每 0.25，都标了数值）。
先在图上按刻度读出「这道题从 0.18 到 0.35」，再 `--span 0.18:0.35` ——
比对着缩略图肉眼估准得多，实测不用刻度会差 0.02 以上，直接把选项行切掉。

| 写法 | 用途 |
| --- | --- |
| `--span 0.18:0.35` | **首选**。整宽、纵向区间（0~1），试卷基本是单栏纵向排版，一题一条横带 |
| `--span 0.18:0.35 --x 0.0:0.5` | 双栏卷子 / 一张图拍了两页，按栏分开 |
| `--box 120,80,900,420` | 像素框；或给 0~1 的小数（服务端自动识别比例） |
| `--index 2,4-5` | 用 `analyze` 的自动候选编号，最省事但检测粒度很粗 |

**边界怎么取**：
- 取在相邻两题之间的**空白行**上，宁可多留一点白，也不要把下一题的题号框进来。
- 裁完**必须打开裁图看一眼**（`--save-dir` 会把图存到本地）。常见的两种偏差：
  选项最后一行被切掉 → 把上界 `+0.01`；框进来上一题的尾巴 → 把下界 `+0.01`。
- 自动切题（`--index`）在密集试卷上往往只给出「上半天 / 下半天」两三大块，
  别指望它一题一块；它的价值是给出大致分区，细切还是靠 `--span`。

**手机横拍的卷子**（长边 4032 那种）：题目仍然是从上到下排的，`--span` 照常用，
不要因为图是横的就去找 `--x`。只有「一张图里左右并排两个版面」才需要 `--x`。

`crop` 加 `--save-dir %TEMP%/mm_intake/<这批的名字>`，脚本会把每张裁图下载到
本地并打印路径，直接 `Read` 那个路径看图。

## 2. 字段口径（决定这份题库好不好用）

| 字段 | 写法 |
| --- | --- |
| `subject` | 数学 / 物理 / 化学 / 生物 / 语文 / 英语 / 历史 / 地理 / 政治。**按图判，不要按题号猜**；化学方程式、实验装置图别记成数学 |
| `question_type` | `选择题（单选）` `选择题（多选）` `填空题` `解答题` `证明题` `其他`。多选由你判断：正确项 ≥2 就是多选 |
| `stem` | 完整题干、所有选项，公式用 `$...$`。多行用**真换行**（`\n` 转义），不要写成字面量 `\n`。选择题保留「（　　）」占位。**不要**把红笔批注、对勾、分数抄进题干 |
| `answer` | 选择题只写字母，多选按字母序连写（`ACD`）；填空题按空序给出；解答题只给最终结果并带单位，不写过程 |
| `error_reason` | 学生的错因，落到**方法/思路/概念**层面（"把单调区间当成定义域用"），不要写"计算粗心"这种不可行动的话。图上有批改痕迹时据此还原错在哪一步 |
| `solution_fix` | 三段：`方法：<教材上的通用叫法>` → `触发点：<题干里让你想到它的那个特征>` → 完整推导。关键步骤补一句为什么能这么做；换元写新变量范围；分类讨论交代依据与边界取不取；末句结论与 `answer` 一致 |
| `solution_alt` | 确实更巧的解法才写，`另法：<名称>` + 两三句说清省在哪；没有就留空，不要硬凑 |
| `knowledge_points` | 数组，2~4 个，用教材上的知识点名（"线面垂直的判定"），不要写章节号 |
| `difficulty` | 1~5 整数。1 课本例题级，3 常规考试中档，5 压轴 |
| `notes` | 只写你**确实不确定**的地方：字迹看不清、图缺了一块、答案被涂掉。这些要让人来补 |

方法名用你判断题目时真正用到的那一招，不要为了填字段编一个。

**不确定就留痕**：看不清的符号用 `□` 占位并在 `notes` 说明，比猜一个错值好——
猜错的值会让用户以为题抄对了。

## 3. 图形：什么时候重绘、什么时候贴原图

`crop_token` 已经把整题截图存下来了，所以**题干区域不用管图**。要单独处理的是
「图在题目里占一大块、导出时想只要图」的情况：

| 场景 | 做法 |
| --- | --- |
| 图简单、能用 TikZ 准确还原（三角形、坐标系、函数图像、立体几何、电路图） | 给 `figure_tikz`，引擎会编译成 SVG |
| 化学结构式 | 给 `figure_smiles`（`{"苯酚": "Oc1ccccc1"}`） |
| 工艺流程框图 | 给 `figure_flow` |
| 实物照片、实验装置、地图、带汉字标注的示意图、手绘批注压在图上的 | `needs_figure: 1`，导出时贴原题截图 |
| 没图 | 三个都不给，`needs_figure: 0` |

- **TikZ 只写 `\begin{tikzpicture}...\end{tikzpicture}`**，不要 `\documentclass` /
  `\usepackage` / `\begin{document}`；图内不写汉字（没有中文字体，编译会失败）。
- 函数图像用 `pgfplots` 的 `\addplot[domain=a:b]{表达式}`，**不要自己描点连线**。
- 可用 `\usetikzlibrary{calc}` 算中点、定比分点；`fillbetween` 没装，写了必失败。
- 立体图被挡的棱单独写 `\draw[dashed] ...`，不要先画实线再叠虚线（重合等于没画）。
- 只要图形本体、不要题干文字：给 `figure_box: [x, y, w, h]`（**相对整题截图的
  0~1 比例**），服务端会从 `crop_path` 重新裁一块增强图。
- 编译不过不影响入库（会自动退回贴原图），但 `notes` 里最好写一句。

## 4. 查重

`add` 会自动查：拿题干前 12 字检索、按「去空白去标点」后的全文比对。
命中就跳过并返回已有 `#编号`。

- 用户重复发同一张图是常态（同一份卷子分几次发），跳过是正确行为。
- 真想再录一份（比如同一道题两种错法）加 `--force`。
- 题目被改过（多了一句小问）不算重复，会正常入库。

## 5. 批量节奏（图很多时）

- **一次上传 ≤8 张**（脚本已自动分批）。10 张以上先 `upload` 全部，再逐张处理，
  不要一张一张传——每张一个请求太慢。
- **逐张推进，不要攒**：一张图的题写完就入库，再处理下一张。中途网络/进程挂了
  已入库的不会丢。
- 给用户进度反馈时用「第 3/12 张，已入库 7 道」这种格式，别只报总数。
- 超过 20 张先跟用户确认一下（是不是真的要全录），但**不要**因为量大就降低抄写质量。

### 用户只是把图贴进对话、没给文件路径

先看消息里有没有给本地路径（对话附件通常落在临时目录，`Read`/`ViewImage` 能读到的那个）。
- **有路径** → 正常 `upload`，走完整流程，原题截图能存下来。
- **拿不到路径**（图只在对话里）→ 仍然可以录：省掉 `crop_token`，字段照常写，
  在 `notes` 里写「原题截图未存，需在页面重新框选」。导出时该题没有截图，
  但题干、解析、题图都正常。
- 别为了拿路径去截屏/另存——直接问用户「这批图在哪个文件夹」更快。

## 6. 收尾

1. `add` 的最后一行会列出 `#编号`；再 `get` 抽 1~2 道回读，确认题干完整、
   公式没被吃掉、`crop_url` 有值。
2. 向用户汇报：**入库几道、编号列表、跳过的重复题、notes 里留了哪些待确认的点**。
3. 提醒：页面 Ctrl+F5 刷新；编号会以浅灰印在卷面上，方便核对。

## 7. 排错

| 现象 | 原因 / 处理 |
| --- | --- |
| `连不上 http://127.0.0.1:8765` | 服务没起。让用户双击 `启动.vbs`，别自己抢端口 |
| `HTTP 403 ... 访问令牌已失效` | 服务重启过，令牌变了。重新读 `data/.session_token`（脚本每次运行都会读，重跑即可） |
| `HTTP 400 选区太小` | 框小于 20×12 像素，重新 `--span` |
| 裁图里选项最后一行被切掉 | 上界加 0.01~0.02 重裁；对照刻度尺别靠猜 |
| 上传 `HTTP 400` 且提示格式 | PIL 解不开（HEIC 常见）。让用户转成 JPG/PNG，或用系统截图重存 |
| 题干里的公式在页面显示成红字 | `$` 数量不匹配（奇数个）。数一遍，别漏闭 |
| 页面上看到 `\n` 两个字符 | 字段里写了字面量，`add` 会拦下报错；改成真换行 |
| 导出的题图是 AI 画的歪图 | 该题应 `needs_figure: 1`（图太复杂画不准），改完重新保存即可 |

## 8. 不要做的事

- ❌ 调 `/api/ai/solve`、`/api/ai/test` 或任何 `/api/ai/*` 接口。
- ❌ 把红笔批改、对勾、分数、页眉页码抄进 `stem`。
- ❌ 图看不全时凭想象补全图形或题干——写进 `notes` 交给用户。
- ❌ 导入前不跑 `--dry-run`（校验器能挡掉 80% 的低级错误）。
- ❌ 为了让「入库数好看」而跳过 `notes`、把不确定的答案填成确定值。

# AI 错题整理

本地运行的错题整理工具（**支持多学科**，不只数学）：上传试卷照片 → 自动切题 → AI 解析（题干 / 错因 / 解析 / 另解）→ 存入题库 → 组卷导出 PDF / DOCX。

- **后端**：FastAPI + SQLite（单文件，无外部数据库）
- **前端**：原生 ES Module + Canvas 框选，KaTeX 本地渲染
- **导出**：Edge/Chrome 无头打印生成 PDF（每页左上角姓名、右上角日期、页脚页码）；Word 原生公式（OMML）生成 DOCX
- **默认只监听 `127.0.0.1`**，不出网、不开端口给局域网

---

## 1. 快速开始

```bat
:: 首次安装（已带 .venv 可跳过）
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

:: 题图渲染需要 node 依赖（node-tikzjax，约 50MB；不装则题图退回贴原图）
npm install --ignore-scripts

:: （可选）批量导入 AI 配置；也可以在界面右上角齿轮里手动填
:: .venv\Scripts\python.exe tools\import_ai_config.py --mysql 用户:密码@主机/库名

:: 启动
.venv\Scripts\python.exe start.py
```

启动方式三选一：

| 方式 | 命令行窗口 | 适合 |
| --- | --- | --- |
| 双击 `启动.vbs` | **不出现** | 日常使用（推荐）。输出写进 `logs/launcher.log` |
| 双击 `启动.bat` | 保留 | 排查启动问题，报错直接显示在窗口里 |
| `.venv\Scripts\python.exe start.py` | 保留 | 开发调试 |

启动后浏览器会自动打开 <http://127.0.0.1:8765/>。

**关闭服务**：点页面右上角的 ⏻（设置面板底部也有一个）。走的是 `POST /api/shutdown`，
uvicorn 正常收尾——关连接、刷日志、释放端口，不是硬杀进程。关掉后页面会变成一张
「服务已关闭」的提示卡，再要用就再双击一次 `启动.vbs`。

> 依赖：Python 3.11+、Node.js 18+（用于服务端公式渲染）、Microsoft Edge 或 Chrome（导出 PDF）。

## 2. 界面与流程

| 步骤 | 说明 |
| --- | --- |
| ① 上传 | 拖入或粘贴试卷照片，支持一次多张。图片会重新编码以剥离 EXIF，同时做透视校正与去倾斜。 |
| ② 切题 | 行投影算法按"行距突变"切块，支持双栏版面；居中大标题会单独切出。红笔/蓝笔痕迹用 HSV 分离，标出疑似错题并给出置信度。 |
| ③ 确认 | 点框勾选/取消；空白处拖拽可自建框；拖动边框可微调；右键删除；Delete 删除选中框。 |
| ④ 解析 | 先选「解析学科」（切换后记进设置），再逐题调 AI（默认并发 2），结果进入题目队列。 |

队列里每道题有明确状态，右侧直接给出能做的操作：

| 状态 | 含义 | 可做 |
| --- | --- | --- |
| 待解析 | 排队中 | 取消（移出队列） |
| 解析中 | 请求模型 | — |
| 待入库 | 解析完成，还没存 | **入库**（不开抽屉直接存）、点整行审核 |
| 已入库 | 已进题库 | **编辑**（改动存回同一道题） |
| 失败 | 请求失败/格式不可用 | **重试**、× 移除 |

- 同一块题目重复点「AI 解析」不会重复入队，只会复用原记录
- 「继续 N」「重试 N」「清理」「清空」只在有对应内容时出现
- 队列落 localStorage：刷新/误关页面不会丢掉已经花钱买回来的解析结果
  （两个标签页同时开着时，没有动过队列的那个不会覆盖存储）
- 已入库的项点开是**编辑这道题**，改完存回同一条，不会又新建一道
- 抽屉里改了没保存就关（Esc / 点遮罩）会先问一句
| ⑤ 审核 | 点队列项打开抽屉：左边原题截图 + 公式实时预览，右边可改题干、答案、错因、解析、另解、知识点、题图。`Ctrl+Enter` 保存。 |
| ⑥ 题库 | 搜索题干/答案/错因/知识点，按学科筛选；收藏、编辑、删除、加入试卷。 |
| ⑦ 组卷 | 设置标题（默认「M月D日错题」）、学科、来源、姓名、日期、排版方式、答案位置（题后/卷末）、是否保留题图、每题留白行数，预览排版后导出 PDF / DOCX。 |

### 多学科

学科不是装饰，它直接决定提示词：

| 学科 | 公式处理 |
| --- | --- |
| 数学、物理 | 走 LaTeX：`$...$` 行内、`$$...$$` 独立成行，命令用完整花括号 |
| 语文、英语、化学、生物、历史、地理、政治等 | 走纯文本：禁止 `$...$` 与 `rac`，需要上下标时用 Unicode（H₂O、x²），避免界面里出现一堆反斜杠 |

设置页可改默认学科；识别页的「解析学科」下拉切换后立即生效并记住；每道题还能在编辑抽屉里单独改学科，题库可按学科筛选，试卷也能单独标学科（不是数学时会印在卷头）。

### 两种排版

| 版式 | 用途 | 内容 | 纸张 |
| --- | --- | --- | --- |
| 标准试卷 | 整卷练习 / 打印带回家 | 题干 + 错因 + 解析 + 另解 + 答案 + 知识点（按勾选项） | A4 纵向，页眉姓名、右上日期、页脚页码 |
| **裁切粘贴** | 剪下来贴进笔记本 | **只有题目和错因**，题与题之间一条虚线剪切线 | 也是 **A4**，但正文收进中间 15.8cm 一列，四周留 24mm/26mm |

**两种版式都是 A4**：打印机不用改纸、不会被驱动缩放。裁切版靠留白而不是改纸宽——
16 开是 185×260mm，从 A4 居中剪成 16 开要各切掉 12.5mm（左右）和 18.5mm（上下），
正文只占中间 158mm，四边留 24~26mm，剪歪五六毫米也切不到字。
有手工裁好的纯图形或 `needs_figure` 时会带上图（高度压到 40mm），纯文字题不贴整块截图（否则题干印两遍）。

### 试卷库

每次**导出 PDF/DOCX 时自动存一份到试卷库**，可以有多份。每份显示标题、日期、题数、姓名，并支持：

| 操作 | 说明 |
| --- | --- |
| 预览 | 在弹层里看排版效果 |
| PDF / DOCX | 用当时的题目与选项重新导出 |
| 载入 | 把这份试卷的题目、标题、姓名、日期和导出选项整套还原到编辑区；再次导出会**更新同一份**而不是新建 |
| 删除 | 只删记录，题目本身不受影响 |

切到「组卷导出」标签页会自动刷新列表。

### 题图（几何图形）

模型手写 SVG 坐标是最容易翻车的一环：它得自己在 400×300 像素里换算，标签位置靠估，
曲线只能用折线凑，属性还可能被折行劈开（真实踩过 `<text x="1 95">`）。
所以改成**模型写 TikZ、本地编译**：

| 环节 | 做法 |
| --- | --- |
| 模型输出 | `figure_tikz`：一段 `\begin{tikzpicture}…\end{tikzpicture}`，用世界坐标描述几何关系 |
| 编译 | `node-tikzjax`（TeX 引擎编成 WebAssembly）在常驻 node 进程里编译成 SVG，只需本地 node，不用装 LaTeX |
| 存储 | 编译结果写回原有的 `figure_svg` 字段，**导出层零改动** |
| 预览 | 编辑抽屉里可改 TikZ 源码，点「渲染预览」后端编译；不点也行，保存时会自动编译 |
| 失败 | 编译不出来就退回「附原题截图」，源码保留让用户自己改 |

为什么 TikZ 更准：`\draw (3,0) rectangle (3.4,0.4)` 的直角标记自动贴着坐标轴方向，
`\node[below left] at (0,0) {$B$}` 的标签由引擎避让，函数图像用 pgfplots 真采样，
都不是手算像素能比的。

**图里不写汉字**：TeX 引擎不带 CJK 字库，图中文字一律用 `A/B/C`、`a/b/c`、`\alpha`、
`\angle ABC`、`x/y`，中文写在题干里。必须用汉字标注的示意图（如"甲""乙"、实物图）
自动走 `needs_figure=true` 贴原图。

> TikZ 输出里的 `<text>` 用 TeX 字体（cmr10 等），字体文件在 `web/vendor/tikz/`，
> 页面和 DOCX 栅格化都会加载；缺了也不会崩，只是字形退化成系统衬线体。

还有一条退路：**保留原图**。图形复杂（照片、统计图、手写标注）时置 `needs_figure=true`，导出时自动附上原题截图。

截图常把题干文字一起带进来。编辑抽屉里的「题图裁剪」可以在原图上拖一个框，只留图形本身：框选后后端按归一化坐标（0~1）裁成新图存盘，导出优先用这张图。裁剪弹层会把图片自动缩到窗口能装下的尺寸（矮屏也不会把图裁掉、框选不到），窗口缩放时选区跟着重算。

PDF 里 SVG 直接矢量渲染；DOCX 里先用无头浏览器把 SVG 栅格化成 PNG 再插入（Word 不认内联 SVG）。

## 3. AI 配置

三种填法，任选其一：

1. **界面里直接新增/编辑**：右上角齿轮 → 「添加 / 编辑服务」展开 → 填名称、`base_url`、
   API Key、模型列表（逗号分隔）→ 「保存这条配置」。同一个折叠区还能改名、换地址、
   换 Key、删除当前这条；Key 留空就表示"不修改"，不会被清掉。
2. **界面里拉取模型**：选好服务 → 「从接口拉取模型」→ 选模型 → 「测试连通性」；
3. **命令导入**：`tools/import_ai_config.py` 支持 `--mysql 用户:密码@主机/库名`、
   `--config-php 某个 PHP 配置文件` 或 `--from-json 导出的 JSON`，
   把 `name / base_url / api_key / models` 一次性写进去。

对应的接口（前端用的就是这三个，也可以直接 `curl`）：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/settings/configs` | 新增一条：`{name, base_url, api_key, models}` |
| `PATCH` | `/api/settings/configs/{id}` | 修改；`api_key` 不传 = 沿用旧 Key，传 `null` = 清空 |
| `DELETE` | `/api/settings/configs/{id}` | 删除；删的若是当前服务，自动切到下一条 |

不管哪种方式，Key 只写进 `data/config.json`（`0600` 权限），前端只拿到掩码与 `has_key`。

**JSON 输出策略**：默认请求 `response_format={"type":"json_object"}`。若接口报"不支持"，自动降级为文本模式并记住结论（按"配置+模型"记录），下次直接走文本模式。文本模式使用固定分节标记（`[[题目]]`、`[[错误原因]]`…）保证可解析。

## 4. 数学公式处理（重点）

模型输出的 LaTeX 不能直接信任，这里有五层防线：

1. **硬折行还原**：真实模型会按固定宽度把长文本折断，换行点随机落在
   `\frac` 与 `{` 之间、`\` 与 `mathrm` 之间，甚至 JSON 的 `"solution_alt"` 键中间。
   这些换行不携带语义，解析前整段删除（只有两侧都是英文单词才补一个空格）；
   模型用 `\n` 显式写的换行则原样保留，充当分段/选项分行。
2. **公式内安全收紧**：只删除紧贴 `^ _ { } ( ) ,` 的空白、数字中间的空格（`2 026` → `2026`）。
   绝不全局删空格 —— `\ln x` 会变成未定义命令 `\lnx`，比原问题更糟；`\text{ ... }` 内的空格保留。
3. **定界符归一**：`\(...\)`/`\[...\]` → `$...$`/`$$...$$`，`equation`/`align` 环境改写，
   Unicode 数学符号（× ≤ ∈ △ …）在公式内转成 LaTeX 命令。
4. **前端渲染**：KaTeX，渲染失败会保留原文并标注，同时汇总到「公式体检」。
5. **导出**：PDF 走浏览器排版（KaTeX 字体 base64 内联）；DOCX 走 MathML→OMML 原生可编辑公式。

历史数据可用 `python tools/repair_questions.py`（加 `--apply` 写回）批量修复，
它会把"整段原始 JSON 塞进题干"的降级题重新解析。

字面量 `\n`（多转义一层留下的两个字符）可用 `python tools/scan_literal_escapes.py` 扫，
更全面的体检用 `python tools/audit_question_text.py`：一次列出字面量转义、HTML 残留、控制字符、JSON 尾巴、`$` 定界符奇数、零宽字符，`--apply` 修可确定的那几类。
加 `--fix` 就地改回真换行。判据是查 TeX 命令表：`\notin`、`\theta`、`\to`、`\node`
这些原样保留，只有 `\nA. …`、`\n所以` 这种才替换。

### 解题方法提示（数学 / 物理）

错题本的价值不只是"这题怎么做"，而是"下次怎么想到"。所以解析开头强制两行：

```
方法：<教材上的通用叫法>
触发点：<题干里让你想到它的那个特征>
```

- **方法**用教材上的通用叫法，别自创词；物理题用物理的叫法；
- **触发点**写"看到什么条件想到它"，这一句才是可迁移的部分；
- 整套推导、符号按教材写法来，学生能照着写进答题卡；
- 原思路完全走不通时，整套（方法 + 触发点 + 正确过程）写进「另解」，两处不能都没有。

提示词**只管形状，不管具体用哪一招**：列"可用技巧"清单会替模型预设思路，点名禁用某些
定理也会把那些词塞进上下文，两者都不写。

### 解析失败会明确报错

模型"答了但不能用"时，不会再静默地把原始 JSON 当题干——那会让用户看到满屏
`\frac` 和 `\n`，比报错更难处理。现在的判定与处理：

| 情况 | 处理 |
| --- | --- |
| 能修好（折行、`\ in`、中文引号、`1⏎.0`、乱码、单反斜杠…） | 正常返回，`strategy` 记为 `json:*` |
| 整体坏了但字段完整 | 逐字段抢救（`json:salvage`），并提示"部分字段可能缺失" |
| 明显是 JSON 却完全解析不了 / 缺 `question_text` | **HTTP 422**，前端红色提示，原始响应存到 `logs/ai/` 供排查 |

上游 5xx、超时仍是 502，与"内容不可用"区分开。

解析器对抗的破损形态（都有回归测试）：

- 中文引号被当成 JSON 定界符（`“三线合一”` 提前闭合字符串）
- `"confidence": 1`⏎`.0` —— 数字被折行劈开
- `\ in` / `\ mathrm` / `\ le` —— 反斜杠与命令名之间被塞空格
- `\ x_2` —— 这是 LaTeX 控制空格，**不能**合并成 `\x_2`（按已知命令表判定）
- UTF-8 被当 cp1252 解码的乱码（`æ±‚å¯¼å¾—`）
- `[[[ ... ]]]` 包裹、字符串里野引号导致定界扫描跑偏

### 配色

导出物与网页预览共用一套语义配色，扫一眼就能分清板块：

| 板块 | 颜色 |
|---|---|
| 错误原因 | 红（`#9e1f16`，淡红底 + 左侧色条） |
| 解析 | 蓝（`#0d5c86`） |
| 另解 | 绿（`#0b6b52`） |
| 答案 | 靛（`#263c9c`） |
| 知识点 | 琥珀（`#7a5a12`） |
| 判对/判错 | 「正确」绿粗、「错误」红粗（只匹配独立词，不误伤「正确性」） |

PDF 用 `print-color-adjust: exact` 保证打印出来也带色。

一条公式要穿过四道关卡，每道都有降级路径：

```
AI 输出 → 归一化 → 存储 → 渲染（KaTeX）→ 导出（PDF 用 KaTeX HTML，DOCX 用 OMML）
```

1. **归一化**（`app/ai/parser.py::normalise_latex`）
   - `\(...\)` → `$...$`，`\[...\]` → `$$...$$`，`equation/align` → `aligned`；
   - Unicode 数学符号（× ≤ π √ ∠ …）在公式内转成 LaTeX 命令；
   - 修掉模型/gateway 的典型污染：`\ frac` → `\frac`、汉字之间的多余空格、句中硬换行；
   - 花括号/`$` 不配对时给出警告，不阻断保存。
2. **存储**：题干/答案/解析统一为 Markdown + LaTeX（`$…$` 行内、`$$…$$` 独立成行）。
3. **界面渲染**（`web/js/math.js`）：直接构造 DOM（不走 innerHTML），KaTeX `throwOnError`，失败处显示红色原文并在编辑器给出警告。
4. **导出**
   - PDF：Node 调用 KaTeX 批量渲染成 HTML；字体 base64 内联，`displayMode` 与界面一致；矩阵/分段函数等"高公式"即使行内书写也自动提升为块级，避免行高被撑爆。
   - DOCX：LaTeX → MathML（latex2mathml）→ OMML（Office 自带 `MML2OMML.XSL`），是**可编辑的 Word 公式**；转换失败时按原文 `$…$` 保留并在控制台记录。

## 6. 安全设计

- 只绑定 `127.0.0.1`；Host 白名单拦截 DNS rebinding（返回 421）；
- 所有写操作要求 `X-App-Token` + Origin/Referer 同源校验 + JSON Content-Type，阻断跨站表单；
  令牌随机生成后存于 `data/.session_token`（0600），**跨重启保持不变**，重启服务后旧页面仍可继续用；
- CSP：`default-src 'self'`，脚本仅本地文件，`object-src 'none'`，`frame-ancestors 'none'`；
  另放行 `worker-src 'self' blob:`，否则浏览器扩展注入的脚本会刷一片 CSP 报错（不影响本程序功能）；
- 上传：magic bytes 校验 + PIL 解码 + 重新编码（剥离原始字节、EXIF），限 20MB / 8000 万像素；
  单文件失败只记入 `errors` 并继续处理同批其余文件；同一张图按 sha256 去重；
- 资源访问一律用服务端生成的不透明 ID，不接受用户路径；
- AI 返回的 HTML/SVG 一律按白名单重建，不执行脚本、不加载外链。

## 7. 已知限制

- 切题是启发式算法：手写与印刷混排、无题号的连续解答可能被切成一块，需手动调整（拖拽/新增框）。
- 手写内容靠视觉模型识别，工整度影响准确率；建议拍照时保持纸面平整、光线均匀。
- DOCX 的题图是 PNG（栅格化），并非矢量；需要矢量请导出 PDF。
- 单用户、单机使用；没有账号体系与并发写保护（SQLite 已串行化写入）。

## 8. 常见问题

**Q：提示"尚未配置 AI 服务"？**
在界面右上角齿轮里填一个服务（`base_url` + API Key + 模型）即可；
也可以运行 `tools\import_ai_config.py` 批量导入，再到设置里选模型。

**Q：导出 PDF 很慢/失败？**
需要 Edge 或 Chrome。程序优先走 DevTools 协议（带页眉页码），失败时回退到 `--print-to-pdf`（无页眉）。

**Q：Word 里公式变成普通文字？**
说明该公式 `latex2mathml` 无法转换（例如自定义宏）。控制台会打印清单，改成标准 LaTeX 即可。

**Q：图片题没有图？**
模型对复杂图形会选择"保留原图"，此时题目必须保留原题截图（导出选项「保留原题截图」或题目里勾选）。也可以用编辑器的 SVG 文本框自己补一张。

**Q：控制台里 `Failed to load resource: 403 ... /api/images`？**
服务重启后页面手里的令牌会过期。程序会自动拉一次新令牌并重试，正常不会弹错；
若反复出现，是 `data/.session_token` 被改动过，刷新页面即可。

**Q：控制台里 `Permissions policy violation: unload is not allowed`？**
这是浏览器扩展（`contentScript.bundle.js`）自己注册 `unload` 监听触发的，Chrome 已废弃该事件，与本程序无关，不影响使用。

**Q：iPhone 拍的 HEIC 能直接传吗？**
可以（依赖 `pillow-heif`）。文件选择框的 `accept` 已包含 HEIC；若运行环境缺少该依赖，会提示改拍 JPG 而不是静默失败。
单张超过 20MB 会被拒绝并显示实际大小；一次拖太多张时前端会按「10 张 / 24MB」自动分批。
